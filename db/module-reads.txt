# db/module-reads.txt — the shape that modules 2 (send-managed) and 3 (send-byo) REQUIRE of the two platform-owned tables public.users and public.job_items.
#
# SOURCE. Read from the modules' CODE at the pins in tools/modules.lock (M2 02a71fc, M3 d6ac497), not from their comments, fixtures or pre-flight text: Docs/phase-1-spec.md "Inventory" (the module
# constraints) and findings F19-F22. Each statement behind a line below is in db/module-statements.txt, which scripts/check-module-reads.sh holds against the module source (red when the code starts
# reading something this file does not list). tests/harness/shape_test.go compares THIS file with the catalog of a migrated database (TestShape_*), and platform_0001_public_tables.up.sql is written to it.
#
# THE RULE THIS FILE ENCODES. Module 3's test-send runs `INSERT INTO public.job_items (campaign_id, user_id, recipient_email, rendered_subject, rendered_body, status) VALUES (...)` as send_byo_app
# (statement J4): six columns. So EVERY OTHER column of public.job_items must be nullable or defaulted, whatever the platform adds later (a test fails on one that is not, whether declared here or not).
# public.users is never written by module code (its role holds SELECT only), so the rule does not apply there; its columns are declared in full so that the table cannot change unnoticed.
#
# LINES (`|` separated; the whole file is read by a parser that refuses a malformed line, tests/harness/shape_helpers_test.go):
#   <table>|<column>|<type as format_type prints it>|NOT NULL or NULL|default (yes or no: a default expression, an identity or a generated column)|required_by|note
#   pk|<table>|<column>                               the primary key is exactly this one column
#   fk-present|<table>|<column>|<schema.table>        the column has a foreign key to that table
#   fk-absent|<table>|<column>                        NO foreign key of any kind involves the column (either direction)
#   row|<table>|<column>|<value>|<required_by>|note   a row with that value must exist
#   accepts|<table>|<column>|<value>|<required_by>|note   the column must accept that value (a probe INSERT, rolled back)
# required_by: m2 / m3 / m2,m3 = module CODE (non-test) reads or writes the column; test-only = only the modules' own test seeders touch it (module code never does); platform = only the platform needs it.

# ---- public.users: module code reads exactly one column, id (EXISTS on it, and 7 + 11 foreign keys point at it) ----
public.users|id|uuid|NOT NULL|yes|m2,m3|primary key and foreign-key target of 7 (m2) + 11 (m3) module constraints; the only column module code reads (SELECT EXISTS(...WHERE id=$1), statements U1/U2). A text id would break every FK from the modules' uuid columns.
public.users|auth_user_id|uuid|NULL|no|platform|the link to Supabase auth.users (foreign key, unique). NULL only for the all-zero system user (users_auth_link; finding F19).
public.users|email|text|NOT NULL|no|test-only|no module code reads it; the modules' test seeders insert it (INSERT INTO public.users (email, is_active) ...). Normalised: trimmed, lower-case, unique.
public.users|is_active|boolean|NOT NULL|yes|test-only|no module code reads it; the modules' test seeders insert it. The platform's own switch for a login that may no longer act.
public.users|created_at|timestamp with time zone|NOT NULL|yes|test-only|no module code reads it; the modules' manual scripts ORDER BY it.

# ---- public.job_items: read by M2 and M3 (J1, J2), WRITTEN by M3's test-send (J4: the six columns named above) ----
public.job_items|id|uuid|NOT NULL|yes|m2,m3|primary key and foreign-key target (jobs.job_item_id ... ON DELETE CASCADE); M3's INSERT omits it, so it must have a default (gen_random_uuid()); RETURNING id.
public.job_items|campaign_id|uuid|NOT NULL|no|m2,m3|read into a non-pointer Go string (a NULL is an opaque 500); copied into jobs.campaign_id UUID NOT NULL; J4 binds ONE parameter to this column and to user_id, so both are uuid. NO foreign key and NO check: M3's test-send writes the user's own id here.
public.job_items|user_id|uuid|NOT NULL|no|m2,m3|read (WHERE user_id = $2, tenant scoping) and copied; written by J4. Must exist in public.users or the job's genesis event fails its foreign key.
public.job_items|recipient_email|text|NOT NULL|no|m2,m3|copied into jobs.recipient_email TEXT NOT NULL; written by J4. A NULL becomes an opaque 500 (SQLSTATE 23502 is not mapped by the modules), not a 4xx.
public.job_items|rendered_subject|text|NOT NULL|no|m2,m3|copied into jobs.rendered_subject TEXT NOT NULL; written by J4.
public.job_items|rendered_body|text|NOT NULL|no|m2,m3|copied into jobs.rendered_body TEXT NOT NULL; written by J4.
public.job_items|reply_to|text|NULL|no|m2,m3|copied into jobs.reply_to TEXT (nullable); J4 omits it, so it must stay nullable or defaulted.
public.job_items|rendered_text|text|NULL|no|m2,m3|OPTIONAL plain-text alternative of rendered_body (Phase 3 close-out B3/C5): NULL, '' or white space only means no plain-text part and the message is the single HTML part it has always been; a real text makes the module build multipart/alternative (text/plain first). Read by J2 of both modules, copied into their own jobs.rendered_text (nullable, 1 MiB cap on the module side); module 3's J4 omits it, so it must stay nullable.
public.job_items|unsubscribe_url|text|NULL|no|m2,m3|the ADDITIVE carrier of List-Unsubscribe (Phase 5 S3, platform_0017): NULL, or one https URL with no white space, angle bracket or control character, at most 2000 bytes (CHECK job_items_unsubscribe_url_shape). The PLATFORM writes it (internal/jobs, for every item of a send job, the signed per-recipient link); modules 2 and 3 READ it in J2 once their Phase 5 change is pinned (chunk S4: List-Unsubscribe: <url> and List-Unsubscribe-Post: List-Unsubscribe=One-Click when it is set; db/module-statements.txt does not list the new J2 text until then), so it is declared here as required by both. Module 3's J4 omits it, so it must stay nullable.
public.job_items|status|text|NOT NULL|yes|m2,m3|WRITTEN by J4 as the literal 'pending' and, since Phase 4 (close-out D9), READ by the run route of M2 and M3 (J1 and J2): an item whose status is 'cancelled' (the platform's terminal marker for an item it never submitted, set when its job expires, is cancelled or fails before submission) is refused with 409 job_item_cancelled; every other value, and NULL, runs as before. Must accept 'pending' and 'cancelled'; the platform owns the rest of the vocabulary.
public.job_items|created_at|timestamp with time zone|NOT NULL|yes|platform|used by no module and no module test. Defaulted because J4 omits it.
