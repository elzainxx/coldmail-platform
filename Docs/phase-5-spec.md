## Decisions taken (one line each; none is irreversible)

1. **Grammar.** Merge field `{{name}}` / `{{name|fallback}}` (name `[A-Za-z_][A-Za-z0-9_]*`, at most 64); spintax `{a|b|c}` with at least two options, nestable to depth 8; escapes `\{ \} | \\`; `{{` always opens a field; a stray `}` or an unclosed group is an error with its position (a brace for CSS or script must be escaped). Reserved fields: `email` and `unsubscribe_url`.
2. **Missing means absent or empty after trimming**; a field with a fallback never counts as missing; the fallback is template text (not escaped).
3. **Seed** = first 8 bytes of SHA-256(`job_id` + `:` + `item_id`); `item_id` is the row id the platform already hands every module, so a preview sample is exactly what will be sent. HTML and the text part share one spin stream, the subject has its own; the choice generator is implemented in the package (no library whose algorithm can change).
4. **Plain text:** an explicit text template is rendered; a blank one is generated from the rendered HTML (links kept as `text (url)`), so every message has a text part.
5. **Unsubscribe token** is `base64url(item_id (16 bytes) || HMAC-SHA256(secret, "unsub|v1|" + item_id)[:24])`: short, no address in the URL, no enumeration (a bad MAC and an unknown item answer alike). `GET` shows a confirm page and changes nothing (link prefetchers); `POST` (the form, or the RFC 8058 one-click body) suppresses. Both need `PLATFORM_UNSUBSCRIBE_SECRET` (at least 32 bytes) and `PLATFORM_PUBLIC_BASE_URL` (https); without them a send job cannot be confirmed, and a send job that was confirmed earlier writes no item (it waits) rather than send without its link.
6. **Modules carry the headers through one additive nullable column** `public.job_items.unsubscribe_url` (a single https URL, never a free header map: no header injection surface); each sender emits `List-Unsubscribe: <url>` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click` when it is set, through a builder that refuses anything but printable ASCII https without angle brackets within one 998-octet line.
7. **Retention placeholders:** after 7 days `rendered_subject` and `rendered_body` become `[removed]` (the modules' columns are NOT NULL), `rendered_text` and `unsubscribe_url` become NULL; the link in a sent message keeps working (it is derived from the item id).
8. **Vendor opt-out** is a per-user setting, default opted in, read once into the job when it is created (a later change never alters a job that exists); an opted-out job reserves at the non-vendor price and module 1 receives the policy without the `external` block, named by module 1's own `describe` (`vendor_fallback.opt_out_policy`); an opted-out job whose module 1 does not report that key cannot be confirmed (it never falls back to the default policy).
9. **Pause limit:** a job paused from running more than `PLATFORM_JOB_PAUSE_MAX_DAYS` (7) is cancelled by the engine through `cancelling` (so the module cancels its unclaimed items); a job paused before its start is cancelled straight; the clock is the database's.
10. **Owner rulings recorded:** M3 `campaign_expiry_sec` 30 days; `debug_log_retention_days` 7 and the promotion dates (retention +14 days, account purge +14 more, shadow modes after 14 quiet days) are checklist rows; master key without rotation accepted for V1 (a record for the owner to sign); TLS terminates at one public Caddy edge in front of the platform API and web app only, the modules private; M1 failure-origin section 4 cases stay `undetermined`; pause and resume wording stays as it is; disclosure texts are drafted in P8.
11. **A row the shared table cannot take** (a message over the size limits, a blank subject after rendering) is found at confirm and skipped free as state `unrenderable` (`P-10`), instead of failing the whole job after the credits are held.
12. **The footer is decided per rendered part, after rendering:** each part gets the footer unless its own rendered text already shows the link (the visibility test is the text conversion of the HTML); a link swallowed by a comment or an unclosed tag makes the row `unrenderable` (reason `no_visible_unsubscribe_link`), never sent; `{{unsubscribe_url}}` inside a spintax option is refused at save (the placement must be unconditional).
13. **Preview samples** (up to 3 real rows rendered exactly as they will be sent) are returned in the response and never stored in `platform.jobs.preview` or its fingerprint (they hold recipient data).
14. **A cached vendor-derived answer** may answer an opted-out job (no call is made for it) and is charged as any cache row; an opted-out job never writes an entry that would shadow the vendor policy.
15. **Template and merge data are kept** after the 7 days (`platform.jobs.frozen_settings` content, `job_rows.fields`, the raw address): clearing them is irreversible, so it waits for the owner (recommendation in the report: clear the template and the merge data at the same 7 days, keep the outcomes).

## Findings and things noticed (none blocks this phase)

- **Fixed in this phase after the review:** the footer was decided from the template, not the rendered message (decision 12); the access log could hold a token that arrived as `//u/<token>` (the path is cleaned before the prefix test); a store with no link maker wrote items with a NULL link (decision 5).
- **Found by the runner, not by any local test:** the sink's list endpoint ignores a recipient query, so an older style of suite fetched the newest message (the new suites match the recipient exactly; `phase3_text_part.sh` and `phase8_variation.sh` of module 3 use the old query and pass only because each fetches the message it just sent); a cancel racing the engine's second batch ended unsubmitted rows as the platform's own cancelled results (the send matrix now waits until every row is handed over before it pauses or cancels).
- **Later phases:** a CSV header such as `First Name` can never be matched by `{{...}}` and nothing warns the user (P6: show the usable field names); `Job` does not expose `paused_at`, so the user app cannot say when a pause will be cancelled (P6); all recipients share one rate bucket behind the Caddy edge until the deployment sets a trusted forwarded-for header (P8); a draft saved before this phase with a raw `{` in its CSS now gets a 400 at preview and must be escaped (no real jobs exist).
- **Docs of the modules that still carry an old count or sentence** (a docs-only commit with a CI run each, deliberately not made): module 2 and module 3 `architecture.md`, `install-and-deploy.md` and the root `README.md` say 15 gates and 7 self-tests (there are 16 and 8); module 3's ADR-0021 says the campaign-expiry default is 7 days (it is 30); module 3's `real-infra.yml` `paths-ignore` lacks the new accepted-risk page, so editing it starts a full run; module 1's shadow modes have no environment loader (promoting one is a code change, the L+14 row says so) and its default `TM_LISTEN_ADDR` binds every interface (go-live row G1.18 asks the operator to bind the private address).
- **Module 2's `jobs` table keeps the frozen link after the 7 days** (it holds no address; the link is a capability for that one recipient, derived from the item id).
