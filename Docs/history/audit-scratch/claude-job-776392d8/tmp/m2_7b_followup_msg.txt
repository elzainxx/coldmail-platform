2. THE DESCRIBE SUMMARY ASSERTED THE EQUALITY IT HAD JUST DENIED. contract_drift's
   describe block printed

     contract_drift: describe declarations derived-and-served — N error codes
     (== codeStatus), 2 db_enum + 2 module_constant vocabularies (== declaration source)...

   unconditionally, after its own FAIL lines. On module 3 that produced
   `7 error codes (== codeStatus)` in the same output as
   `FAIL: describe publishes 7 error codes, codeStatus declares 8`. This file had the
   identical line; nothing had made it print yet only because this module's describe
   happened to be consistent -- the defect was latent, not absent.

   WHY THE OBVIOUS FIX DOES NOT WORK, recorded at the fix site: `desc_fail_baseline="$fail"`
   … `[[ "$fail" -eq "$desc_fail_baseline" ]]` is jammed, because `fail` is a 0/1 LATCH,
   not a counter. Every site assigns `fail=1`, so once any earlier check in the script has
   fired the baseline is already 1 and `1 -eq 1` passes for the rest of the run. That was
   tried on module 3 and verified by running it -- the misleading line printed again,
   unchanged. ANY guard of that shape anywhere in the gate layer is jammed the same way.
   Replaced with a block-local flag wired into all 15 in-block assertion sites.
