WHY NOTHING CAUGHT IT. tests/harness/run.sh names each package explicitly and
never runs `go test ./...`; CI runs gofmt, `go vet ./...`, and this script. `go
vet` type-checks test files WITHOUT running them, so an unwired package compiles,
vets clean, and the harness prints a green total that never included it. Not a
missed signal — there was no signal.

run.sh already warned about this in prose (internal/httpapi's first test file
landed with item 7b, commit e3fee99, and nothing ran it). The warning was correct
and did not prevent the recurrence, because a comment cannot enumerate a package.

Both need no database and no stack (verified with every TEST_* variable unset), so
they are listed before any template build.
