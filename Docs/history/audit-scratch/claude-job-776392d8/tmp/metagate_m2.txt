THE CLASS. Four times across this project, work that was written, correct, and
passing has been executed by NOTHING:

  * internal/httpapi's first test file (item 7b, e3fee99) — no line ran it.
  * internal/workerlink + internal/workerproto HERE — 3 tests, 0 skips, all
    passing — found unwired by a cross-repo audit and wired in 2e8be72.
  * module 3: config_consumption_selftest.sh, a BLOCKING control the workflow
    never named, plus four more Go packages (31 tests) from the same audit.

There was no signal to miss in ANY of them, which is the difficulty: run.sh names
each Go package explicitly (deliberately — each suite gets its own PASS/FAIL line)
and CI runs gofmt + `go vet ./...` + the harness + each gate by name. `go vet`
TYPE-CHECKS test files WITHOUT running them. So an unwired package compiles, vets
clean, and the harness prints a green total that silently excludes it. Identical
signals, different truth.

WHY A COMMENT WASN'T ENOUGH. run.sh has carried a prose warning about exactly this
since the httpapi incident — and workerlink/workerproto accumulated behind it
anyway. A warning comment is not a control. The fix for "someone might forget X"
is never a note reminding them; it is a mechanism that fails when X is missing —
the same reasoning as the ADR-0008 grants invariant and config_consumption.

THIS REPO IS ALREADY CLEAN on both rules: 9 packages with test files, all
enumerated; 6 gates, all named in the workflow. That is deliberate timing — the
gate is added to keep a clean tree clean, not to clear a backlog. It also means
the gate's only observable behaviour here is printing OK, which is precisely why
the paired control is not optional.

DESIGN NOTES (identical to module 3's, deliberately — one mechanism, two repos)
  * NO EXEMPTION LIST. This project's history is several instances of an exemption
    quietly becoming permanent. If a package has test files, it runs.
  * FILESYSTEM DISCOVERY (find), not `go list ./...`. Needs no Go toolchain, and
    it SEES a directory whose test files do not compile — which `go list` reports
    as an error rather than as a package, exactly when you most want to know.
    vendor/ is excluded, and so is Docs/, which holds the gitignored reference
    codebase and its own nested .git.
  * Rule 2 covers this gate itself but CANNOT detect its own absence from the
    workflow. That hole is why the selftest's rule 0 asserts BOTH scripts are named
    in CI, and why both are wired in this same commit.
